# 構成図のレビュー

- [ ] 元の入力にある構成要素と接続が図に反映されている。
- [ ] 架空の製品、頻度、接続、所有者が事実に混入していない。
- [ ] ノードIDが一意で、接続の両端が存在する。
- [ ] 主経路、用途、責任境界をラベルから追える。
- [ ] パイプラインの後続工程が右側にあり、連続工程の上下積みや左側への折り返しがない。上下配置は並行経路に用いている。
- [ ] データ線と制御線が区別され、凡例と一致している。
- [ ] 現状、提案、未確認事項が区別されている。
- [ ] 色を見分けなくても役割を理解できる。
- [ ] 実際の表示でラベルの切れ、重なり、過剰な交差がない。
- [ ] 実構成の根拠と提案を区別し、参照する設計資料を明記している。外部調査メモは成果物に含めていない。
- [ ] 公式アイコンの最新版を作成・更新・公開時に確認し、manifestに記録している。
- [ ] 不要なカード、色、装飾、繰り返しラベルを減らしている。

レンダラーが利用できない場合は構文と参照整合性を点検し、描画確認が未実施であると報告する。

- [ ] 各製品・領域・経路が実際の情報に対応している。
- [ ] 全要素が同じカードや5色に機械的に分類されていない。
- [ ] 見出しと配置だけで主経路、基盤の中心、利用先を読める。
- [ ] 公式アイコンの最新版確認・取得元・ハッシュが記録されている。
- [ ] 製品名と役割が区別され、余分な英文見出しや装飾的なバッジがない。
- [ ] ブログ幅960px・スライド幅1280px（掲載寸法が既知ならその寸法）の全体表示で文字が読め、線とラベルの重なり・不要な交差がない。
- [ ] 比率を合わせるための空白や、所属ノードから離れすぎた領域境界がない。元のpx値だけでなく縮小後の文字サイズも確認した。
- [ ] 複雑な処理は別図や本文へ分け、1枚に詰め込んでいない。

判断基準は[原則・基本要素・作図部品](../README.md)を参照する。


## 領域とv2描画の確認

- [ ] 囲いの名前と含む要素が一致し、工程・所属・責任を区別できる。
- [ ] 製品内の論理層と、別プロジェクトの同じ製品を区別している。
- [ ] 入れ子の領域とノードが親の範囲に収まり、見出しやラベルに枠が重ならない。
- [ ] 品質・カタログ・実行管理等の横断機能が主経路のデータ移動として誤読されない。
- [ ] 接続口、分岐・合流、文字と線の干渉を実際の描画で確認した。
- [ ] 旧版の保存・SVGのみ等の編集範囲を守り、再生成で直接編集を上書きしていない。

`python3 scripts/validate_diagrams.py`はv2モデルとSVGのID・接続・所属・文字の概算範囲を確認する。フォント依存の実際の幅や意味上の正確性は描画・原典のレビューで確認する。
