# 構成図の生成

## 入力

最低限、図の目的、対象範囲、分かっている構成要素とデータの流れを集める。可能なら読み手、現状／提案、クラウド・環境、所有者、更新方式、出力形式も確認する。

重大な不明点は質問し、回答を得るまでの下書きでは未確認事項として示す。ユーザーから自由設計を依頼された場合は、補った構成を「提案」と明記する。

## 手順

1. 入力をノード・接続・境界に整理し、事実と提案と未確認事項を分ける。
2. 主な利用目的に合わせて構成パターンを選ぶ。複数ある場合はレーンまたは別図に分ける。
3. データの主経路を左から右に置き、横断機能を下に追加する。
4. 表現ルールに沿って色、ラベル、線種を適用する。外部入力をMermaid構文へ直接埋め込まず、引用符や特殊文字をエスケープする。
5. 製品が確定している場合は[公式アイコン運用ルール](../governance/icon-updates.md)に従い、最新配布物を確認して取得記録を残す。
6. 編集可能なソースと説明を作り、[レビュー](review.md)を実施する。

## 出力契約

構成検討やMarkdown内の共有にはMermaid `flowchart LR`、公開用の完成図にはSVGまたはdraw.ioを標準とする。編集元を必ず添える。選択基準は[編集元と画像出力の選択](export.md)を参照する。

出力にはタイトル、目的・対象範囲、現状／提案、図のソース、凡例、主要経路の説明、前提、未確認事項、参照元を含める。該当しない項目は「なし」と書く。外部事例を自社構成の証拠として引用しない。

[情報モデル](input-model.md)、[構成パターン](../patterns/README.md)、[基本要素と部品の索引](../README.md)を参照する。


## 共通SVG部品

[モデル v2](input-model.md)を使い、`python3 scripts/diagram.py path/to/model.json --output path/to/diagram.svg`で描画する。実体の位置は明示し、内容に合わせる領域だけ`fit`を利用する。まず工程と所属、製品内部の層を整理してから座標を決める。

[名前付き領域](../components/boundary.md)、[横断機能](../components/cross-cutting.md)、[ノード](../components/node.md)を組み合わせる。共有部品はSVGを出力し、draw.io・Mermaidの自動生成は今回のv2では提供しない。

ユーザーがSVGのみの修正を指定した場合、他形式やモデルへ変更を広げない。直接編集されたSVGを再生成する際は差分を確認し、最新の編集を消す再生成を行わない。旧版を残す指示では、新しいディレクトリへモデル・SVG・説明を作る。

`python3 scripts/validate_diagrams.py`で構造・所属・経路・文字領域を確認する。最終成果物はブラウザでも描画し、掲載寸法で確認する。自動チェックだけで可読性を保証しない。
