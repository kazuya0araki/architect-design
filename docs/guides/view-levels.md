# 図の表示レベルと種類

最初に読み手の質問を一つ決め、`view_level`と`diagram_type`を選ぶ。表示レベルは情報の粒度、種類は説明の視点であり別の軸である。以下は本システム独自の分類で、C4の階層と同一ではない。

| view_level | 読み手と質問 | 載せるもの | 省くもの |
| --- | --- | --- | --- |
| `context` | 関係者：何を受け取り、誰へ提供するか | 接続元、基盤を代表する1要素、利用者、対象範囲 | 内部のRaw・Mart、個々のジョブ、ネットワーク |
| `pipeline` | 技術者：どこで保存・加工・提供するか | 処理責務、論理層、製品、所属、必要な横断機能 | サブネット、詳細な認証、再試行順序 |
| `detail` | 実装・運用担当：具体的にどこへ配置・接続するか | 確認済みの配置、接続口、対象に関係する経路 | 関係しない全社構成 |

| diagram_type | 用途 | 推奨レベル |
| --- | --- | --- |
| `context` | 基盤と外部の関係。基盤内部は展開しない | `context` |
| `data_flow` | データの移動、変換、照会、結果 | `pipeline`または`detail` |
| `deployment` | 所属とネットワーク配置、接続口 | `detail` |
| `component_catalog` | 作図部品の見本。実システムの構成を表さない | 見本の説明に応じて選択 |

既存v2との互換性のため両項目は任意だが、新規作成時は明記する。レンダラーは未知の値、context図とpipeline/detail、deployment図とcontext/pipelineの組み合わせを拒否する。抽象度の意味上の正しさは人がレビューする。

一枚で質問に答えられなければ概要と詳細を別モデルに分ける。文字を縮小して全情報を詰めない。複数図は同じ実体のIDまたは`entity_id`で対応を記録するが、現時点でモデルから自動的に表示レベルを切り替える機能はない。
