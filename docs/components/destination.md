# 接続先

## 目的と適用条件

データ基盤のデータや分析結果を利用するツール、システム、ファイル、利用者を表す。製品名と業務用途を分け、利用者・利用経路が必要なら明示する。

## 分類と表現

| 種類 | 例 | 表示する内容 |
| --- | --- | --- |
| BI | Looker、Tableau、Power BI | 製品名とダッシュボード等の用途 |
| スプレッドシート | Excel、Google Sheets | 製品名と分析・配布等の用途 |
| 内製・業務プロダクト | 社内アプリ、顧客向けサービス、外部SaaS | システム名と提供する機能・データ |
| 人・チーム | アナリスト、事業部、データサイエンティスト | 役割とアドホック分析等の目的 |
| 出力ファイル | CSV、Excelブック、レポート | 成果物名・形式と配布先 |

Excelで直接参照する構成と、Excelファイルを書き出す構成を区別する。Google Sheetsについても、参照・書き込み・手動転記等の確認済みの方式を接続側へ記載する。製品名から接続方式を推定しない。

## 人によるアドホッククエリ

概要図では「DWH → アナリスト（アドホック分析）」で参照結果の流れを表せる。ツールが重要なら「DWH → SQLクライアント → アナリスト」と分ける。利用ツールが未確認なら架空のクライアントを追加しない。

クエリ実行指示も説明する場合は「利用者 → DWH」を破線の制御線、「DWH → 利用者」を実線の参照結果として別々に示す。SQL文をデータ取り込み経路として扱わず、実行指示と結果の矢印を混同しない。

## 作図規則

- 原則として基盤の右に配置する。活用先が複数なら用途ごとに縦に並べる。
- 製品は[公式アイコン](../foundations/iconography.md)と正式名称、人は役割名を持つ矩形または`assets/`に保管した汎用アイコンで示す。特定クラウドの製品アイコンを人や内製システムへ転用しない。
- 業務システムへ結果を返す経路はReverse ETL等の目的を示す。同じシステムが接続元でもある場合は、[情報モデル](../guides/input-model.md)に沿って同一性と方向を管理する。
- 人が利用者であることから、権限やアクセス制御が実装済みとは判断しない。

接続方式と矢印は[接続](connector.md)、用途と利用者の書き方は[ラベル](annotation.md)に従う。
