# 製品・処理ノード

同じ寸法のカードに全要素を押し込まず、説明する対象から表現を選ぶ。

| `representation` | 適用先 | 配置 |
| --- | --- | --- |
| `icon` | 製品が確定した処理・保存先・利用ツール | 公式アイコン、その下に製品・処理名、役割 |
| `horizontal` | 狭い横帯、運用領域、縦に並ぶ活用先 | アイコンの右に名前と役割 |
| `logical` | 内製処理、未確定の製品、論理的なインターフェース | 簡潔な矩形と名前・役割 |
| `data` | 製品内部の保存層・論理データ | 控えめな円柱。公式アイコン自体は加工しない |

名前と役割は別項目にする。製品名・役割を小さくして詰めず、意味の区切りで改行する。図用の短い`display_name`・`display_role`を設定しても、根拠となる`name`・`role`は保持する。

Cloud Run上のdbt等、実行基盤と使用ソフトウェアを併記する場合は同じノードの`icons`に並べる。これは別サービスや追加の処理工程を意味しない。単体ツールが変換を管理する範囲を説明するときは、対象製品領域にまとめてもよい。

同一製品内の層は[論理層](logical-layer.md)に従う。別プロジェクトの同じ製品を勝手に統合しない。接続元・接続先の実体は[情報モデル](../guides/input-model.md)の一意なIDで管理し、見た目をまとめてもGCS・S3等の異なる製品を一つの実体へ潰さない。
