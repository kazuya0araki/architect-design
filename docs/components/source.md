# 接続元

## 目的と適用条件

データ基盤へデータを提供するシステム、ファイル、ストレージ、イベント等を表す。製品名だけでなく、何のデータをどのインターフェースから受け取るかが分かるようにする。

## 分類と表現

| 種類 | 例 | 表示する内容 |
| --- | --- | --- |
| 他システム | 業務アプリ、外部SaaS、内製システム | システム名と提供データ |
| データベース | 業務DB、外部の分析基盤 | 製品名または論理DB名とデータの用途 |
| ファイル | CSV、JSON、Excelブック | データ名と確認済みの形式 |
| ストレージ | オブジェクトストレージ、共有フォルダ | 製品名・論理的な受け渡し場所 |
| イベント | アプリイベント、ログ、メッセージ | 発生元とデータの種類 |

ファイルは受け渡すデータ、SFTP・API・CDC等は接続方式として区別する。「ファイル連携」だけで接続元を表さず、分かる場合は提供システムとファイル名・形式を示す。受け渡し場所が重要なら「業務システム → CSV受領場所 → 取り込み処理」と分ける。

ファイル生成元が未確認なら「売上CSV（提供元未確認）」等とし、実在する製品を推定しない。ExcelファイルとExcelアプリ、CSVファイルとその保存場所は異なる要素として扱う。詳細が不要な概要図ではまとめ、まとめた範囲を説明する。

## 作図規則

- 原則として基盤の左に配置する。データを提供する側から受け取る側へ実線矢印を引く。
- 製品が確定している場合は[公式アイコン](../foundations/iconography.md)を使う。未定のシステム・ファイルは矩形とラベルで示す。
- バッチ、ストリーム、手動連携をラベルで区別し、頻度や方式が不明なら未確認事項に残す。
- 同じシステムがデータを受け取る場合もある。[接続先](destination.md)との関係は接続ごとに判断する。

案件固有のシステム名・形式・方式・頻度は[入力の情報モデル](../guides/input-model.md)に沿って案件の構成データへ記録する。共通規則に実案件の一覧を混在させない。
