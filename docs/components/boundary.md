# 名前付きの領域と境界

関連する要素を枠でまとめ、枠の上部に領域名を置く。見出しだけの装飾では所属範囲を示せない場合、工程・機能も配下の要素と一緒に囲む。読む順序しか意味しない空の列を囲ったり、すべての工程を同じ高さに揃えたりしない。

| 種類 | 表す意味 | 基本表現 |
| --- | --- | --- |
| `stage` | 接続元、取り込み、基盤、活用等の機能上のまとまり | 細い枠＋薄い見出し帯 |
| `functional` | 用途・機能範囲 | 細い内枠、名前を上部に配置 |
| `cloud` / `project` | クラウド・アカウント・プロジェクトへの所属 | 薄い背景＋所属名。枠は必要なときだけ |
| `team` | 管理・責任の範囲 | 名前付きの枠。破線を使う場合は意味を説明 |
| `product` | 同じ製品の内部 | 製品名・公式アイコンをヘッダーに置き、論理層を内包 |
| `operations` | 横断機能の対象範囲 | 対象の下部に横長の領域 |
| `contract` | 公開インターフェースと合意された責任 | 明示した契約名と管理主体。DB枠だけで代替しない |

工程と所属は別の軸である。`stage_id`は読む順序・機能の分類、`region_id`と領域の`parent_id`は所属の階層を表す。所属領域を工程領域の中に配置できるが、視覚上の包含をVPC・IAM・セキュリティ分離の保証と解釈しない。

入れ子は意味が必要な範囲に限定する。名前だけ違う枠を重ねない。枠の内側に文字とアイコンの余白を確保し、線は見出しを避けて側面や下辺を横切る。領域の大きさは所属要素と線の通路から決める。自動的に合わせる場合は`fit.members`を使い、通路が必要な場合は明示座標で確保する。

色・線幅は[色](../foundations/color.md)、寸法は[余白](../foundations/spacing.md)、データ項目は[情報モデル](../guides/input-model.md)を参照する。
