# 接続

| 表現 | 意味 | Mermaid |
| --- | --- | --- |
| 実線の片方向矢印 | データの移動・参照結果 | `-->` |
| 破線の片方向矢印 | 実行指示・管理 | `-.->` |
| 名前付きの領域 | 明記された所属・責任・環境・機能 | `subgraph` |



線は水平・垂直を基本に折れを減らし、共有経路はバスとしてまとめる。矢印をアイコン・文字・枠見出しへ重ねない。接続線は1〜1.5pxを初期値とする。

パイプラインを「折り返さない」とは、処理順を左から右へ保つことであり、すべての線を直線にすることではない。合流・分岐のための直角の曲がりは許容する。連続工程の上下積みや右から左への戻りを避けるため、まずノード配置を調整する。実際の書き戻し・クエリ指示等の逆向き通信は意味を変えずに別経路として示し、下部からの実行制御は破線で区別する。

双方向連携は目的別の2本の矢印にする。参照結果の方向とクエリ実行の方向を混同しない。確認済みのデータ名・方式・頻度のうち必要なものだけを記す。

ワークフローに内包される実処理は所属枠または制御線で示し、データの移動と実行指示を同じ線にしない。[凡例](annotation.md)も添える。


## 関係の意味と接続口

`kind`は`data`と`control`を維持し、`purpose`で`ingest`、`replicate`、`transform`、`publish`、`query`、`share`、`notify`、`orchestrate`、`validate`、`reverse_etl`等の目的を記す。必要な目的だけ使い、線の意味を色数で増やさない。`method`や`frequency`は確認済みの場合だけラベルに反映する。

共有経路は単一の通路に揃え、合流・分岐が曖昧な場合のみ小さな接続点を置く。接続点は経路上に置き、単なる交差に点を置かない。線はノード・領域の辺へ接続し、図形やラベルの中央を横切らない。逆向きの実データ経路を示す場合は`return_path: true`と目的を指定する。制御線を使って実際のデータ移動を隠さない。
