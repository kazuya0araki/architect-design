# アイコンの選択と配置

製品が確定したSaaS・クラウドサービスは原則として公式配布のアイコンを使う。図の新規作成・改訂・公開前に公式配布ページを確認し、その時点で提供される最新の推奨セットを使う。「常に最新」はこの確認を毎回行う運用を意味する。日付が新しいことを推測するだけでは最新版確認にならない。

公式アイコンがない論理層、内製処理、製品未定ノードは、文字と汎用図形で示す。公式素材を取得できなければ製品名のテキストで下書きを作り、アイコン未確認を記録する。取得不可のまま最新版確認済みとして公開用完成扱いにしない。

人・組織・汎用データベース等の概念には[Google Fonts Material Symbols](https://fonts.google.com/icons)を使う。Outlined、FILL=0、weight=400を基本に、公式SVGを`assets/icons/material-symbols/`へ保存し、取得元・ハッシュ・ライセンスを記録する。製品が特定できる場合は汎用記号より公式製品アイコンを優先する。

製品名が似ていても、別製品のロゴを流用しない。例えばData Studio（旧Looker Studio）とLookerは区別し、Data Studio公式サイトの専用素材を使う。クラウドのカテゴリ指定と製品ブランドの対応が曖昧な場合は、対象製品の公式素材を確認する。

## 描画時の扱い

- 縦横比、形、色、公式の余白を保持する。再着色、トリミング、回転、反転、装飾の追加をしない。
- アイコンの近くに製品名を置く。ロゴだけで製品を判別させない。
- Azureの公式ガイドは変形や切り抜き等を禁止している。提供元の使用条件を確認し、本システムの寸法規則より優先する。
- 第三者パッケージ、絵文字、検索結果の画像、過去のブログ図からの切り抜きを公式素材の代替にしない。
- 複数クラウドの色や形の違いは保持し、周囲の余白とラベルの位置で揃える。

地域別の公式ページで配布リンクや更新案内を確認できない場合は、提供元の別言語の公式ページを確認する。AWSでは[英語の公式ページ](https://aws.amazon.com/architecture/icons/)も利用できる。確認結果は素材のmanifestに記録する。

製品アイコンは56pxを基準とし、32〜64pxで視覚的な大きさを揃える。縦横比と公式の余白を維持する。製品が確定したら[公式素材の取得・更新](../governance/icon-updates.md)を実施する。

Mermaidは構造検討とテキスト共有に使い、公式アイコンと配置を厳密に扱う完成図にはSVGまたはdraw.ioを使う。
