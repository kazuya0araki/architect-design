# 余白とレイアウト

- データパイプラインの工程は処理順に左から右へ配置する。連続する工程を上下へ積んだり、後続処理を左側へ戻したりしない。
- 上下の並びは複数入力・並行処理・分岐した活用先に使い、合流点・分岐点を揃える。紙幅に収まらない場合は概要と詳細へ分け、経路を折り返して詰め込まない。
- オーケストレーションは対象全体の下部に横長の領域として配置し、上向きの制御線で作用範囲を示す。製品の所属プロジェクトは維持する。
- 収集・蓄積・加工・提供の列幅は情報量に合わせる。列幅やノード数の対称性を目標にしない。
- 同じ製品の論理層は1つの製品領域へまとめる。横断機能は対象の基盤内の下部に置く。
- 枠は所属・責任・環境・機能・工程の実際のまとまりに使う。工程の名前と配下の要素を一緒に囲い、読む順序しか意味しない空の列は囲わない。
- 8pxグリッド、外周48〜64px、領域内24px、ノード内16px、ノード間32px以上、列間64px以上を初期値とする。線ラベルの長さに応じて通路を広げる。
- 図中にはノード名・役割・接続ラベル・領域名等、構成を読むための情報を置く。タイトル・説明文・凡例・出典・前提・未確認事項は付随Markdownに置き、明示の指定がある場合のみ画像内へ追加する。SVGの非表示の`title`・`desc`はアクセシビリティ用として保持できる。
- 16:9はスライド用の初期比率。比率を合わせるためにキャンバスや領域だけを伸ばさない。ブログ用は内容に合う縦横比へ切り詰め、スライドでは図を十分な大きさで配置する。
- 情報密度は工程間隔や領域内の余白で調整し、外周の白いマージンまで切り詰めない。文字やアイコンを画像の端へ寄せず、掲載先の背景から区切れる余白を保つ。
- 入力・利用先の並行レーンはラベルが衝突しない間隔まで詰め、領域の高さは所属ノードと接続の通路に合わせる。下部の運用領域は横長のまま、アイコンと文字を横並びにして高さを抑えられる。
- 長いラベルは文字を小さくせず意味の区切りで改行する。繰り返す所属表記や詳細説明を短くし、技術的な詳細は付随Markdownへ移す。掲載幅で読めなければ概要と詳細を分ける。

線の通路は[接続](../components/connector.md)、アイコンの寸法は[アイコン](iconography.md)に従う。

## 枠と形状

枠は1px、製品枠の角丸は0〜4px、領域は0〜8pxを初期値とする。ピル型見出し、影、グラデーション、立体表現、全ノードへの太い色枠は標準に含めない。クラウド提供元が定める境界表現を使う場合は公式のガイドを優先する。

## 領域と描画順

領域は所属要素の外接範囲に内側余白と見出しの高さを加えて決める。複数領域を同じ高さに揃える必要はない。共有経路や合流のための通路は外接範囲とは別に確保する。表示名の長さだけでノードや領域の大きさを固定しない。

SVGの描画順は、キャンバス→外側から内側への領域→接続線→アイコン・図形→文字とする。ラベルの位置に白背景を置いて線を読めるようにする場合も、別の文字やアイコンへ重ねない。
