# 規則の追加・変更

共通知識の正本は`docs/`。将来のSkillsには発動条件・入力・参照先・作業手順・出力と完了条件を記述し、共通の作図規則は複製しない。

## 配置の判断

| 情報 | 配置 |
| --- | --- |
| 判断の前提となる価値観 | `principles/` |
| 色・文字・余白・アイコン | `foundations/` |
| ノード・論理層・境界・接続・注記 | `components/` |
| 部品の組み合わせと適用条件 | `patterns/` |
| 入力整理・生成・レビュー・出力 | `guides/` |
| 更新方法と素材管理 | `governance/` |

規則には目的、適用条件、具体的な判断基準、関連規則を記す。例が必要なら`examples/`へ編集元と説明を追加してリンクする。色・寸法などの値の正本は基本要素に置き、各パターンには複製しない。

## 更新手順

1. 変更する規則と、その規則を使う部品・パターン・例を特定する。
2. 規則本文と対応する例を更新し、変更理由を適用条件や判断基準に反映する。
3. `docs/README.md`と`AGENTS.md`の案内を更新する。
4. 相対リンク、旧パス、ソースの構文・接続整合性を確認する。図を変更した場合は実際の描画も確認する。

外部調査メモや企業別の観察記録は保存しない。公式素材の取得元・確認日・ハッシュ・利用条件は素材管理のために保持する。
