# 読みやすさと情報の優先順位

企業の技術ブログや登壇資料に掲載できる、具体的な構成とデータの流れを説明する図を標準とする。白地、薄い領域、公式アイコン、短いラベル、細い接続線を基本にする。図の個性は配色の多さではなく、実際の責務・論理層・利用先を読み取れる構造から生む。

以下を本デザインシステムの標準規則とする。役割ごとの多色カードを一律に並べず、所属・責務・論理層とデータの流れによって情報を整理する。

## 情報の階層

1. 外側の機能領域: データソース、取り込み、データ基盤、提供・活用。要素との対応が曖昧なら名前と配下を囲う。
2. 名前付きの領域: クラウド、製品、責任範囲など、意味のある境界。
3. 製品: 公式アイコンと製品名。必要なときだけ役割の補助ラベルを添える。
4. 製品内の論理層: Raw、Staging、Mart等。製品と同じ大きさのアイコンを繰り返さず、内側の小区画で表す。
5. 接続: データ名、方式、実行指示など、経路の理解に必要な情報。

すべてを同じ寸法のカードに押し込まない。製品名だけで十分な要素はアイコンと文字で示し、保存層・処理・境界を囲う必要がある場合だけ枠を使う。製品未定の論理図では公式アイコンを割り当てず、簡潔な矩形と役割名を使う。

利用者がデータの発生元、処理、利用先を順に追えることを優先する。情報が多ければ概要図と詳細図に分ける。図のために架空のノードを追加しない。
