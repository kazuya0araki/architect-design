# 接続元・接続先の入力定義例

目的: システム・ファイルを接続元、BI・Excel・Google Sheets・内製プロダクト・人を接続先として記述する。

状態: 架空の提案。製品名・接続・用途は入力形式を説明するための仮定であり、実案件の事実ではない。

編集元: [構成データのJSON](model.json)。描画済みの構成図ではなく、[入力の情報モデル](../../docs/guides/input-model.md)に沿うデータ定義例。

共通の描き方は[接続元](../../docs/components/source.md)・[接続先](../../docs/components/destination.md)を参照する。

- 接続元は基幹システムと、提供元未確認の売上CSV。SFTP等の未確認な方式は記入しない。
- Excelは分析用アプリとして定義する。Excelファイルを書き出す場合は`kind: file`の別要素にする。
- 人はアナリストという役割で表す。クエリ実行指示は人から基盤への`control`、結果は基盤から人への`data`とする。
- 基盤は概要用の1ノードとしている。実案件では保存・加工等の内部構成を別途定義する。

未確認事項: JSONの`unknowns`に記載。所有者、頻度、具体的な接続方式や認証情報を推定して補完しない。接続情報には資格情報を含めない。

参照元: 本リポジトリの情報モデルと作図部品。外部の実構成を示す出典はなし。

## 構成図への展開

この最小入力を内部構成へ展開した[論理構成例](../analytics-platform/README.md)と、製品を仮選定した[Google Cloud例](../google-cloud-analytics/README.md)を参照できる。展開した例では基盤を取り込み・受領ストレージ・Raw・Mart・実行管理に分解し、製品名・用途・内部処理を提案として追加する。
